Prompt-injection defence for agents that hold tools

Your agent reads the attacker's email. It will not obey it.

MuffleGuard sits between an AI agent and its tools. It removes instructions hidden in the content the agent reads, and refuses any action whose target was chosen by that content rather than by you.

What you see, and what the model sees.

The problem

Everything an attacker needs, sitting in one inbox.

An agent that reads mail and can send it holds all three at once. Take any one away and the attack dies; an assistant worth having keeps all three.

How it works

Two layers, so one miss is not a breach.

Layer one

Take the sentence out.

Hidden carriers are decoded and removed, and two small CPU classifiers flag sentences addressed to the model rather than to you. Only those sentences go, so the rest of the mail still reaches the agent and the real job still gets done.

Layer two

Ask who chose the target.

Before any outbound call runs, every recipient, URL and path is traced back to where it came from. An address found only in an email was chosen by whoever wrote that email. No model is consulted, so there is nothing to argue out of it.

Underneath

Write down what happened.

Every decision goes into a log where each entry carries the hash of the one before it. Editing an entry afterwards breaks the chain at exactly that entry, and the viewer will do it on request so you can watch it being caught.

The rule the whole design rests on

An outbound tool call may only act on a target the user chose, unless a human approves it.

No model is consulted, so there is nothing to argue out of it. Everything else is detail.

Switch the detectors off

The claim that matters.

Any classifier can be beaten, so the interesting question is what happens when one is. Run the same attack with every content defence disabled: the model obeys the injection, and the call is refused anyway.

What it does not claim

The audit log is tamper-evident, not tamper-proof. URL provenance checks the host only. An address you paste yourself is yours.

Runs on a laptop

The detectors are ONNX on the CPU, so no content leaves for them. The policy engine consults no model at all and decides in microseconds.

Open, and testable

212 tests, CI on a clean checkout, and an evaluation anyone can reproduce without a key or an account.
